# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## O que é

Mente Digital — assistente Omni 100% local (voz + texto), rodando em GPU local (RTX 3080 / Ryzen 9 7950X3D). Backend FastAPI com WebSocket para chat ao vivo (VAD/barge-in), LLM local via `llama-cpp-python`, STT (Whisper), TTS (Piper), e RAG sobre um vault Obsidian indexado em ChromaDB, com fallback para busca web (DuckDuckGo).

Este é o pacote modularizado (V2) de um MVP monolítico anterior (`mvp_mente.py`), preservando os pilares arquiteturais originais: GPU serializada, streaming+chunking de TTS, speculative pre-fetch, ETL post-chat idle, e anti-alucinação via RAG aterrado.

## Comandos

```bash
pip install -r requirements.txt
python main.py                          # ou: uvicorn main:app --host 0.0.0.0 --port 8000

pip install -r requirements-dev.txt     # deps de teste (pytest, pytest-asyncio)
pytest                                   # suíte roda sem GPU/rede (usa fakes)
```

Servidor em `http://localhost:8000`. Há uma suíte `pytest` (pasta `tests/`) cobrindo a
lógica pura e sensível — gate de relevância, buffer anti-sentinela, chunker, latência —
com fakes de LLM/TTS/store (sem GPU nem rede). Não há linter ou build configurados.

**Ambiente:** o projeto roda na env conda `llama-omni` (Python 3.10.20) — o `python` no
PATH do Windows costuma ser o atalho falso da Microsoft Store. Rode via caminho absoluto:
`C:\ProgramData\miniconda3\envs\llama-omni\python.exe -m pytest`.

Configuração via `.env` (prefixo `MENTE_`), sem tocar no código — ex.: `MENTE_N_CTX=4096`, `MENTE_RAG_SCORE_CONFIDENT=0.7`. Todos os campos configuráveis estão em [config.py](mente_digital/config.py).

## Arquitetura

Wiring fino em [main.py](main.py) (lifespan cria os serviços e injeta em `AppContext`); toda a lógica vive nos módulos abaixo. Nenhum módulo de domínio conhece o WebSocket diretamente — o pipeline do agente recebe um callback `send(dict) -> bool`.

- **[config.py](mente_digital/config.py)** — `Settings` (Pydantic), incluindo o dicionário fonético inglês→PT-BR usado pelo TTS.
- **[state.py](mente_digital/state.py)** — `AppContext` (DI container em `app.state.ctx`) e `SessionMemory` (histórico de chat, "memória fresca da sessão", fila de ETL — todas `deque` com `maxlen` para não crescer sem fim).
- **[llm.py](mente_digital/llm.py)** — `LlamaManager`. GPU serializada por um `ThreadPoolExecutor(max_workers=1)` ("gpu-infer"): garante estruturalmente que dois decodes nunca rodam juntos na GPU. Cancelamento (barge-in) usa `stop_event` por requisição; o `asyncio.Lock` só é liberado depois que a thread realmente terminou (sem overlap de VRAM).
- **[audio.py](mente_digital/audio.py)** — `SttService` (faster-whisper / CTranslate2; device via `resolve_device`; suba `MENTE_WHISPER_MODEL=large-v3` para máxima qualidade), `TtsService` (Piper), `SentenceChunker` (quebra streaming de tokens em frases prontas para TTS, ignorando abreviações/decimais, com flush por tamanho). O `TtsService._normalizar` chama `verbalizar` (abaixo) ANTES do filtro `_ALLOWED`/Piper.
- **[verbalizar.py](mente_digital/verbalizar.py)** — verbalização de números PT-BR para fala (PURO/testável, como `agenda.py`). O Piper foneiza via espeak-ng, que ADIVINHA a leitura de número e erra em PT-BR: decimal ("3,5" → vírgula vira PAUSA em vez de "três vírgula cinco"), hora com "h" ("22h42" → "agá" literal) e símbolos ($ % ° º) que o `_ALLOWED` depois APAGA ("R$ 5,50" → "erre cinco…"). `verbalizar(texto)` soletra TUDO em palavras faláveis antes do Piper — cardinais via `num2words(lang="pt")`, estrutura (ordem dos passos, plurais, "e", hora feminina "uma/duas", decimal DÍGITO-A-DÍGITO que preserva zeros) imposta no Python. Cada passo que soletra CONSOME seus dígitos; os que só trocam símbolo (%/°/traço) deixam o número pro passo de inteiro/decimal/milhar no fim. Degrada sem `num2words` (dígito cru, não quebra o TTS).
- **[tts_xtts.py](mente_digital/tts_xtts.py)** — `XttsService`: engine de TTS ALTERNATIVO (XTTS-v2/coqui na GPU), opt-in por `MENTE_TTS_ENGINE=xtts` (default `piper`). Mesmo contrato duck-typed do `TtsService` (`load`/`ready`/`synth_base64`→WAV base64); a fábrica `audio.build_tts()` (usada no `main.py`) decide o backend, com import do coqui/torch **tardio** (o caminho Piper nunca toca coqui → CI/startup leves). Reusa `verbalizar` mas NÃO o filtro `_ALLOWED` do Piper (o XTTS foneiza texto rico). Roda no PRÓPRIO `asyncio.to_thread`, NÃO no executor serializado do LLM (rotear por lá DEADLOCKARIA: o `stream()` ocupa o worker único no turno todo) — logo, na MESMA GPU do LLM há contenção real (VRAM/compute), mitigada por `MENTE_TTS_XTTS_FP16` (default on); o ideal é GPU separada (`MENTE_TTS_XTTS_DEVICE=cuda:1`). Voz embutida (`MENTE_TTS_XTTS_SPEAKER`) ou clone de `.wav` (`MENTE_TTS_XTTS_SPEAKER_WAV`), latentes cacheados no load. DeepSpeed atrás de flag (`MENTE_TTS_XTTS_USE_DEEPSPEED`, off; exige CUDA toolkit + MSVC). Fail-soft: erro no load deixa `ready=False` e o app segue no texto.
- **[rag.py](mente_digital/rag.py)** — `EmbeddingProvider` (singleton; device via `resolve_device`, `auto` usa GPU se houver), `VectorStore` (Chroma com **distância de cosseno** — não o L2 padrão, pois os embeddings não são normalizados e os thresholds do gate são de escala cosseno; reindex incremental por `mtime`, chunking por cabeçalho Markdown via `split_markdown`, dedup por `source`), `WebSearcher` (DuckDuckGo com **fallback de backend** via `buscar_com_fallback`, cache LRU, speculative pre-fetch). **Deep-fetch + RAG efêmero**: o `ddgs.text()` devolve só snippets (título+1-2 frases) — raso demais para perguntas numéricas/específicas, onde o LLM anti-alucinação respondia "Não tenho informações suficientes" mesmo com a web "respondendo". A correção abre o CORPO das top-N páginas (`httpx` async), extrai o texto principal (`trafilatura`), atomiza e RANKEIA os trechos contra a pergunta com o **mesmo embedding do VectorStore** (`rankear_por_similaridade`, cosseno; nada é indexado — RAG efêmero), passando ao LLM só os melhores dentro de um orçamento de chars. Cai de volta pros snippets se o fetch falhar/estiver off (`MENTE_WEB_FETCH_ENABLED=false`) ou sem embeddings (testes). O `EmbeddingProvider` é criado uma vez em [main.py](main.py) e injetado em `VectorStore` E `WebSearcher`. **Trocar a métrica de distância exige recriar o banco vetorial** (apagar `banco_vetorial_cerebro`).
- **[agent.py](mente_digital/agent.py)** — o NÚCLEO do agente (pós-modularização de 2026-07): `Agent.pipeline_resposta`/`_pipeline` (orquestra cache-hit local/RAM → escalada para web, com o buffer anti-sentinela) e o roteamento aditivo de ferramentas (`_rotear`/`_pipeline_tools`). A classe `Agent` compõe dois mixins — [comandos_mestre.py](mente_digital/comandos_mestre.py) ("age") e [respostas.py](mente_digital/respostas.py) ("responde") — que em runtime são o MESMO objeto de sempre. Os nomes históricos seguem **re-exportados por `agent`** (main.py, ws.py, scripts/, eval/ e testes importam de lá); monkeypatch de nome de módulo, porém, mira a casa NOVA do símbolo (ex.: `etl.settings`, não `agent.settings`).
- **[comandos_mestre.py](mente_digital/comandos_mestre.py)** — mixin "age": `_fluxo_mestre` (a máquina de estados da palavra-mestre) + todos os executores de comando das três ondas (agenda/listas, SRS, hábitos, rotinas, gatilhos, pomodoro, navegação, fio, ajuda, revisão diária, conexões, contradições, fontes) e os meta-comandos de sessão (desfazer/corrigir/confirmar/atalhos).
- **[respostas.py](mente_digital/respostas.py)** — mixin "responde": `_responder_contexto` (segura o áudio até provar que não é o sentinela), `_responder_web` (filler falado + escalada), `_responder_stream` (token→frase→TTS), `_sintese_sob_demanda` (map-reduce), `_prefetch` (curiosidade especulativa) e `_consolidar_fontes` (a promoção do `#conhecimento_novo`).
- **[otimizador.py](mente_digital/otimizador.py)** — `QueryOptimizer` (resolve pronomes cruzados via LLM; com o gate léxico do painel, pergunta auto-contida nem paga o LLM) + as heurísticas puras da pergunta: `referencia_contexto`, `extrair_tema_sintese`, `frase_citada`, `lacuna_pesquisavel`.
- **[atomos.py](mente_digital/atomos.py)** — a atomização PURA (`dividir_atomos`, `normalizar_atomo`, `normalizar_malha`, `_slug_titulo`): o LLM entrega a IDEIA, o Python impõe a ESTRUTURA (tags canônicas, `##`, frontmatter de proveniência, wikilinks da Malha).
- **[etl.py](mente_digital/etl.py)** — `EtlProcessor` (destila conhecimento novo em ÁTOMOS Zettelkasten no idle — tanto as pesquisas web da fila quanto o **histórico da conversa** (`summarize_dump` atomiza em vez de gerar um resumo estruturado) e a pesquisa proativa das lacunas — sempre cedendo a GPU para inferência interativa via `ctx.interactive_idle`) e `append_chat_dump` (a fila que o `summarize_dump` consome). **Re-pesquisa de TEMAS QUENTES (#4):** o ESPELHO da lacuna. Lacuna = o que a RAM E o banco NÃO responderam (buraco); tema quente = o que o usuário mais REUSA do banco — toda vez que o estágio Banco responde de fato (parágrafo não-sentinela com `local.fontes`), `agent._pipeline` registra o tema (`db.save_tema_quente`, tabela `temas_quentes`, UPSERT que conta reusos; mesmos guards da lacuna: efêmero/confidencial/`lacuna_pesquisavel`). No idle, `pesquisa_temas_quentes` (após a proativa — buraco tem prioridade) re-pesquisa na web os favoritos acima de `MENTE_IDLE_TEMAS_MIN_REUSO` (3) e fora do cooldown `MENTE_IDLE_TEMAS_COOLDOWN_DIAS` (14d), capado por `MENTE_IDLE_TEMAS_MAX` (2)/ciclo. Diferente da proativa, NÃO há skip Nível-1 por cobertura do banco (o banco sempre cobre o favorito); o valor é a NOVIDADE — o dedup por átomo de `_salvar_atomos` descarta o já-sabido, então só o fato inédito vira nota. `MENTE_IDLE_PESQUISA_TEMAS=false` desliga. **Ciclo de vida do conhecimento** (`#conhecimento_novo`): todo átomo auto-colhido (web + conversa + o contexto amplo do pre-fetch, que é a "curiosidade" enfileirada em `_prefetch`) nasce com a tag `#conhecimento_novo`. Quando um átomo é de fato USADO numa resposta local (estágio Banco não-sentinela), `_consolidar_fontes` remove a tag dos arquivos-fonte (`LocalResult.fontes` reporta quais chunks entraram no contexto) — promoção idempotente e em background. Assim a base cresce da curiosidade do usuário e "amadurece" o que ele realmente reusa. **Um arquivo por átomo** (`_salvar_atomos` + `dividir_atomos`, Zettelkasten puro): a síntese do LLM (vários `##`) é fatiada num `.md` por ideia, então a promoção é precisa por átomo — só o que foi reusado perde a tag, não os vizinhos que calharam no mesmo documento.
- **[tools.py](mente_digital/tools.py)** — function calling ADITIVO. Gate lexical `talvez_acao` (só mensagens de AÇÃO acionam o roteador LLM; pergunta comum não paga a chamada extra → TTFA preservado). Roteador via JSON (`parse_decisao`), não o tool-calling nativo do llama.cpp. `ToolRegistry` + ferramentas (calcular, hora_atual, salvar_nota, listar_notas, ler_nota, buscar_web) e os **agentes de agenda/lista** (criar_lembrete, listar_lembretes, cancelar_lembrete, avisar_quando, agendar_briefing, adicionar_item, ler_lista, remover_item) e a **captura rápida** (capturar_nota → inbox `Inbox_Captura.md` no vault; a revisão/atomização fica pro idle) , o **health-check** (status_sistema → autoteste falável dos serviços .ready), a **trilha de auditoria** (auditoria_hoje → "o que você fez hoje"; ações mutantes têm `auditavel=True` e são gravadas na tabela `auditoria`) e o **modo confidencial** (#5, meta-comando no `_fluxo_mestre`: `mem.confidencial` faz o turno viver só na RAM — sem dump/SQLite/ETL/pre-fetch/lacuna). Loop agêntico CAPADO por `max_tool_steps`; ferramentas `terminal=True` saem no 1º passo. As ferramentas de agenda/lista têm `registra_conhecimento=False`: o turno ("me lembra de X") NÃO alimenta o dump que o idle atomiza — a persistência delas é a tabela/nota, não o Zettelkasten.
- **[mestre.py](mente_digital/mestre.py)** — **palavra-mestre**: um fluxo ISOLADO para acionar os agentes. Quando a mensagem COMEÇA pela palavra-mestre (`MENTE_PALAVRA_MESTRE`, default "mestre"), ela é tratada como COMANDO de agente, não como pergunta — sem a palavra, o pipeline de conhecimento de hoje não muda. `separar` detecta/remove a palavra (só a 1ª conta). `parse_rapido(comando, agora)` resolve os comandos REGULARES por regex, SEM LLM (listas add/ler/remover, listar/cancelar lembrete, alarme só-horário) e devolve `tools.Decisao`; puro/testável, `agora` injetado. O que não casa (lembrete COM mensagem, watcher) devolve None e o `Agent._fluxo_mestre` cai no roteador LLM; se NEM o roteador achar uma ação, o comando é RECUSADO (isolamento rígido) e REGISTRADO em `db.registrar_comando_desconhecido` (tabela `mestre_nao_reconhecido`) como melhoria a revisar. Comando de agente nunca vira conhecimento (não alimenta o dump). **Encadeamento falado (#12, Onda 2):** `parse_composto` (usado pelo `_fluxo_mestre` no lugar do `parse_rapido`) resolve "faz X e faz Y" como VÁRIAS ações — `dividir_comandos` fatia nas fronteiras onde um conector (" e ", "depois", ";") é seguido do INÍCIO de uma nova ação (`_ACAO_START_RE`), então o "e" INTERNO de lista ("leite, farinha e ovos") não vira corte; cada parte passa pelo `parse_rapido`. Se QUALQUER parte não resolve, o TODO defere ao LLM (nunca faz metade). Num composto com ação destrutiva, o `_fluxo_mestre` executa as SEGURAS já e deixa a `confirmavel` aguardando "confirma". **Atalho de intenção frequente (#2, Onda 2):** o `_fluxo_mestre` CONTA cada intenção-mestre resolvida por forma normalizada (`db.registrar_frequencia`, tabela `mestre_frequencia`) e, quando uma cruza `MENTE_ATALHO_SUGESTAO_MIN` (default 3), OFERECE um atalho UMA vez (`_talvez_sugerir_atalho` + `sugerido`). "mestre, atalho <nome>" (`mestre.parse_atalho`) grava o ÚLTIMO comando resolvido (`mem.ultimo_comando_mestre`) sob o apelido (`db.salvar_atalho`, tabela `mestre_atalhos`); no topo do fluxo, um comando que casa um apelido é EXPANDIDO de volta (`Agent._atalhos_cache`, carregado 1x do DB). Só AÇÕES contam como intenção — meta-comandos (desfazer/confirmar/atalho) não. **Desfazer (#8, Onda 2):** `comando_desfazer` (puro) detecta "mestre, desfaça/volta atrás/cancela isso" e o `_fluxo_mestre` executa `mem.ultima_reversivel` — meta-comando de SESSÃO, como o modo confidencial. `mestre.reverter(executadas)` (puro) calcula o inverso de cada mutação a partir do PAR (Decisao, resultado): add↔remove de lista, `criar_lembrete`→`cancelar_lembrete` pelo `#id` que a própria ferramenta reportou; inspeciona o resultado para não "reverter" o que falhou. Toda mutação (rápida OU via LLM, com/sem palavra-mestre) guarda seu inverso via `Agent._lembrar_reversao(mem, ...)`; o undo é consumo ÚNICO (limpa o campo — não se desfaz o desfazer) e a reversão vive só na RAM (não persiste). Captura/nota ainda não são reversíveis (sem inverso registrado). **Corta-e-Corrige (#9, Onda 2):** `tem_correcao`/`parse_correcao` (puros) detectam "mestre, corrige para X / na verdade era X / corrija: era X, não Y" e extraem o valor CERTO (o trecho após "não" é o rejeitado, descartado; radicais `corrig`/`corri**j**`/`correca` porque o imperativo "corrija" não casa "corrig"). `Agent._corrigir` = DESFAZ a última adição (via `mem.ultima_reversivel`) + REFAZ com o valor certo (`mestre.refazer_com` clona a `adicionar_item` original — guardada em `mem.ultima_acao` pelo `_lembrar_reversao` — trocando só o item). Correções encadeadas ficam limpas: o novo alvo de undo é só o REDO. Hoje cobre listas (add); lembrete/captura ficam de fora. **Cofre de confirmação (#25 + #15, Onda 2):** ações DESTRUTIVAS e não-desfazíveis (marcadas `Tool.confirmavel=True` — hoje só `cancelar_lembrete`, que o undo #8 não recria) não rodam de imediato: o `_fluxo_mestre` as STAGE em `mem.confirmacao_pendente` e pede "diga 'mestre, confirma'". `comando_confirmar` executa, `comando_abortar` ("não/deixa"; sem "cancela"/"para" p/ não colidir) descarta, e QUALQUER outro comando abandona a pendência (não prende o usuário). Confirmação REDUNDANTE (#15) é evitada de propósito: o que o undo cobre (add/remove) NÃO é gateado — `_acao_confirmavel` só segura o `confirmavel`. Botão `MENTE_CONFIRMACAO_HABILITADA` (default on); off = executa direto.
- **[agenda.py](mente_digital/agenda.py)** — parser de tempo PT-BR **puro/testável, sem dependência nova** (o instante de referência é INJETADO, como `normalizar_atomo`). `parse_quando(texto, agora) -> (primeiro_disparo, recorrencia)` cobre relativo ("daqui a 10 min"), absoluto ("amanhã às 8h", "meio-dia") e recorrente ("todo dia às 7h", "toda segunda", "a cada 30 min"). O que não casa devolve `(None, None)` — a ferramenta pede pra reformular em vez de agendar no horário errado. `proximo_disparo` calcula a próxima ocorrência de uma recorrência.
- **[scheduler.py](mente_digital/scheduler.py)** — `SchedulerService`: a "responsabilidade contínua" dos agentes tipo-Alexa (o que o ETL idle NÃO é — ele é oportunista, não cron). Loop de background (retido em `ctx.track_task`, iniciado no lifespan) que lê a tabela **`agendamentos`** (persistente: sobrevive a restart) e dispara os vencidos, fazendo PUSH FALADO para as sessões vivas (`ctx.sessoes` → `safe_send` com `{"tipo":"proativo"}` + `{"tipo":"audio"}`; o front abre uma bolha própria com 🔔). Três tipos: `lembrete` (alarme/timer, único ou recorrente), `watcher` ("me avise quando X" — recorrente, a cada checagem busca na web e pergunta ao LLM se a condição ocorreu, `SYS_WATCHER`), `briefing` (flash briefing diário, `SYS_BRIEFING`). **Sem ouvinte não perde**: o disparo vira `pendente_entrega` e é reentregue na próxima conexão (o WS chama `entregar_pendentes` no accept). **Respeita a GPU serializada**: watcher/briefing só chamam o LLM após `interactive_idle.wait()` e com `preemptible=True` — a conversa ao vivo passa na frente, igual ao ETL. **Pesquisa proativa AGENDADA (evolução #1):** o ETL idle é oportunista (roda 1× ao fim de uma conversa); sem sessão a base não cresce. O `tick` também checa `_pesquisa_idle_devida(agora)` e, quando devido, dispara `_executar_pesquisa_idle` em BACKGROUND (`track_task`, para não atrasar o loop de alarmes) — religa o modelo (`ensure_loaded`; `collect` não auto-carrega) e roda `ctx.etl.pesquisa_proativa()` + `pesquisa_temas_quentes()`, devolvendo a VRAM ao fim. Gateado por `MENTE_PESQUISA_AGENDADA_INTERVALO_SECONDS` (default **0 = off**; ex.: 7200 = a cada 2h) — ⚠ **em INGLÊS**: o campo é `pesquisa_agendada_intervalo_seconds`, e a grafia `..._SEGUNDOS` não casa com campo nenhum. Com `extra="ignore"` no pydantic ela é engolida CALADA, então quem escreve em português acredita ter ligado e está com a função desligada (medido em 2026-08-02: `SEGUNDOS=7200` → lê `0`). O `.env` do dono viveu assim desde que a função nasceu: desligado nunca dispara, nunca concorre com sessão viva, uma passada por vez, e uma falha de fundo jamais derruba o scheduler. É o "cresce a noite toda" (pareado com `MENTE_IDLE_TEMAS_MIN_REUSO=1` para o crawler ter alvos).
- **[verbosidade.py](mente_digital/verbosidade.py)** — governador de verbosidade (#7, "Uma Frase Basta"): `classificar(pergunta)` puro decide o tamanho/latência da resposta (factual curta → 1 frase com teto de tokens menor; "explica/por quê/detalhe" → resposta cheia). O `Agent._responder_contexto`/`_responder_web` recebem `max_tokens`/`instrucao_extra` do nível. **Explique-como-para-criança (#45, Onda 2):** um nível `crianca` no MESMO classificador — pedido de SIMPLICIDADE (não de tamanho), então é ortogonal e VENCE curto/detalhado (simplificar precisa de espaço p/ a analogia). Gatilhos "para uma criança / como se eu fosse leigo / linguagem simples / eli5" injetam uma `instrucao` de "explique com analogia do dia a dia, sem jargão"; per-pergunta (stateless), reusa a fiação do #7 (chega ao LLM local E web via `instrucao_extra`).
- **Síntese sob Demanda (#23)** — "o que eu sei sobre X" tem FLUXO PRÓPRIO em `Agent._sintese_sob_demanda` (detectado por `extrair_tema_sintese`, puro): `VectorStore.buscar_conteudos` recupera muitos átomos crus, o pipeline os resume em LOTES que cabem no n_ctx (map, `prompt_sintese_tema_map`) e combina os parciais numa fala (reduce, streaming) — map-reduce que evita estourar o contexto num tema grande.
- **[textutils.py](mente_digital/textutils.py)** — normalização de texto e extração de keywords (sem acento/stopwords) usada para aterramento léxico e limpeza de query.
- **[ws.py](mente_digital/ws.py)** — `LiveSession`: máquina de estados do WebSocket `/ws/chat_live` (VAD por RMS no servidor, barge-in cancela o pipeline em andamento). `_finalizar_sessao` dispara o ETL idle UMA vez, tanto no `end_session` explícito quanto no **disconnect** (rede de segurança: antes, cair a conexão sem `end_session` perdia a atomização da conversa). **Conversas**: o cliente controla a conversa ativa via `set_conversa` (reassocia o id na reconexão), `nova_conversa` (id novo + contexto limpo) e `carregar_conversa` (recarrega os turnos do SQLite na RAM p/ continuar). Todo turno é gravado com `memory.conversa_id`, e o histórico agrupa por ele.
- **[telemetry.py](mente_digital/telemetry.py)** — logs coloridos thread-safe (`telemetry.track/warn/error`) e `Database` (SQLite: histórico de chat com `conversa_id`, log de ETL, métricas, e **latência TTFT/TTFA por resposta** via `save_latency`; a classe `LatencyTracker` mora aqui desde a modularização; médias expostas em `/api/metrics`). **Histórico por CONVERSA** (não turnos soltos): `get_conversations` agrupa por `conversa_id` (turnos legados sem id caem por dia via `COALESCE`) e `get_conversation` devolve todos os turnos de uma para reabrir; endpoints `/api/conversas` e `/api/conversa/{id}`. Migração idempotente adiciona `conversa_id` a bancos antigos. Nunca usar `except: pass` — todo erro passa por `telemetry.error`.
- **[prompts.py](mente_digital/prompts.py)** — todos os prompts de sistema/tarefa centralizados aqui (extrator de query, filler, resposta principal, síntese ETL de web e de conversa). A tag de maturidade é `prompts.TAG_NOVO` (`#conhecimento_novo`); `TAG_ATOMO` é `#zettelkasten_atomico`. O sentinela anti-alucinação (`SENTINELA_INSUF`) também vive aqui — é contrato com o texto do system prompt.

### Pipeline de resposta (`Agent.pipeline_resposta`)

1. `QueryOptimizer` extrai termos de busca da pergunta (resolvendo pronomes via histórico recente).
2. Busca local no `VectorStore` + memória de sessão filtrada por tema (`_ram_relevante`).
3. **Gate de relevância** (correção do "Cache Hit falso" — ver seção abaixo): só é Cache Hit se houver aterramento léxico (chunk menciona keyword da pergunta) OU confiança semântica alta (`distância < rag_score_confident`).
4. Se Cache Hit: responde com streaming, mas segura o áudio/tokens até confirmar que a resposta não é o sentinela anti-alucinação `"não tenho informações suficientes"` — se confirmar, escala para web sem nunca "falar" o sentinela (preserva TTFA).
5. Cache Miss (ou escalada): dispara um filler falado para mascarar latência, busca na web, responde em streaming, e enfileira o resultado para o ETL idle.

**Cascata RAM→Banco→Web + Early-stop (#3, Onda 2):** a fusão roda as fontes em ordem (RAM = memória fresca da sessão; Banco = vault Zettelkasten; Web = fallback). Com `MENTE_EARLY_STOP_CASCATA=true` (default), a cascata PARA na primeira fonte que responde com confiança (passada não-sentinela): se a RAM já respondeu, o Banco **nem é consultado** (pula a busca vetorial E o decode) — troca a fusão multi-fonte por menos passes de inferência na GPU serializada (= menos latência no próximo turno). Desligado, volta à fusão completa RAM+Banco (cada fonte contribui um parágrafo). A Web sempre foi "só se nenhuma fonte local respondeu".

### Correção do "Cache Hit falso"

Ver [README.md](README.md) para o diagnóstico completo. Resumo: o gate antigo tratava "tem algum contexto" como Cache Hit; com um vault grande, quase toda pergunta achava algo vagamente parecido e a web nunca era consultada. A correção exige contexto **relevante** (aterramento léxico via `textutils.contem_alguma` OU `rag_score_confident`). O botão de calibração é `MENTE_RAG_SCORE_CONFIDENT` (default `0.8`; menor = mais rígido/mais web, maior = mais confiança no local) — cada pergunta loga `[LOCAL] melhor_dist=... relevante=...` para calibrar.

### Consultoria TTFT (2026-07-21)

Rodada de latência focada em TTFT/TTFA — relatório completo (banca, debate, ranking) em [CONSULTORIA_TTFT.md](docs/CONSULTORIA_TTFT.md). As 12 aceitas estão implementadas:

- **Waterfall por estágio (#1)**: `LatencyTracker` ganhou `vad_ms/extrator_ms/busca_ms` (preenchidos em ws.py/agent.py), persistidos em `metricas_latencia` (migração idempotente) e expostos como **p50/p95 por estágio** no bloco `waterfall` do `/api/metrics` (`Database.latencia_percentis`). É o que arbitra qualquer otimização futura (incl. os critérios de reentrada do TensorRT-LLM).
- **Dedup na escala do e5 (#2)**: `MENTE_DEDUP_DIST_MAX` 0.08→**0.01** (0.08 era escala MiniLM; no e5 marcaria 75% da base como dup e o `_ja_no_banco` descartava átomo legítimo). Recalibrar SEMPRE junto com o gate ao trocar embedding.
- **Endpointing adaptativo (#3)**: `ws.janela_endpoint` (pura) — fala ≤`MENTE_VAD_FALA_CURTA_SECONDS` (3s) encerra com `MENTE_VAD_SILENCE_CURTA_SECONDS` (0,7s) em vez dos 1,2s; retomada logo após corte curto loga "possível corte precoce" (a taxa que calibra o default). `MENTE_VAD_ADAPTATIVO=false` desliga.
- **Spike Whisper→GPU (#4)**: `SttService.load` cai para CPU/int8 se o load em cuda falhar (`MENTE_WHISPER_GPU_FALLBACK_CPU`) — o spike (`MENTE_WHISPER_DEVICE=cuda` + `MENTE_WHISPER_COMPUTE_TYPE=int8`) tem aborto automático; pior caso = status quo logado.
- **Higiene do DB de teste (#5)**: `tests/conftest.py` redireciona `MENTE_DB_TELEMETRIA` pra um tmp ANTES de qualquer import do projeto (e faz `init()`); as 3 lacunas-fixture do banco real foram expurgadas (backup `telemetria_etl.pre-expurgo-2026-07-21.db`).
- **Bench + guardrail (#6)**: `eval/bench_ttfa.py` — regressão de orquestração com fakes + guardrails (sentinela nunca falado, resposta não-vazia, rota esperada, waterfall preenchido); sai !=0 se violar. Números REAIS vêm do `waterfall` do `/api/metrics`.
- **Filler ∥ busca web (#7)**: `_responder_web` dispara a busca ANTES de sintetizar o filler (a rede trabalha por baixo da fala); short-circuit do `NENHUM` intacto.
- **1º chunk agressivo (#8)**: `SentenceChunker(primeiro_max=…)` — só no 1º chunk, vírgula+espaço fecha frase e o flush usa `MENTE_TTS_CHUNK_PRIMEIRO_MAX_CHARS` (60; 0 desliga; nunca alarga o max). Vírgula decimal não fecha (exige espaço).
- **Fase (b) do extrator (#9)**: quando `QueryOptimizer.pagaria_llm` diz que o LLM vai rodar, `VectorStore.recuperar` (só embedding+HNSW) parte em paralelo e o `search(recuperados=…)` reusa o resultado — o embedding usa a pergunta crua, então é idêntico ao serial. `MENTE_OPTIMIZER_OVERLAP` desliga; fail-open com fakes antigos.
- **Preâmbulo comum (#10, investigação)**: `llm.montar_system` (ponto único) prefixa `prompts.PREAMBULO_COMUM` quando `MENTE_PROMPT_PREAMBULO_COMUM=true` (default **off** — kill criterion: só cravar com A/B real ≥50ms/turno).
- **Threads/CCD do STT (#11)**: `scripts/bench_stt_threads.py` — varredura threads × afinidade de CCD (7950X3D) com fala sintetizada pelo próprio Piper; aplica-se o vencedor em `MENTE_WHISPER_CPU_THREADS`.
- **Gate do bump llama-cpp (#12)**: `eval/retest_speculative.py` — reproduz o crash de shape do prompt-lookup em contexto longo + A/B tok/s; só subir o pin/religar `MENTE_SPECULATIVE_ENABLED` com PASS em env isolada.

### Convenções

- Toda chamada bloqueante/CPU-bound (IO de arquivo, Whisper, Piper, embeddings, SQLite) passa por `asyncio.to_thread`.
- Erros nunca são engolidos silenciosamente — sempre `telemetry.error(modulo, mensagem, exc)`.
- Comentários no código explicam o *porquê* (ex.: por que um lock existe, que bug histórico uma heurística corrige) — mantenha esse padrão ao editar esses módulos.
- STT parcial (transcrição em tempo real/streaming) é uma não-feature intencional — não implementar sem pedido explícito (ver README).
