# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## O que é

Mente Digital — assistente Omni 100% local (voz + texto), rodando em GPU local (RTX 3080 / Ryzen 9 7950X3D). Backend FastAPI com WebSocket para chat ao vivo (VAD/barge-in), LLM local via `llama-cpp-python`, STT (Whisper), TTS (Piper), e RAG sobre um vault Obsidian indexado em ChromaDB, com fallback para busca web (DuckDuckGo).

Este é o pacote modularizado (V2) de um MVP monolítico anterior (`mvp_mente.py`), preservando os pilares arquiteturais originais: GPU serializada, streaming+chunking de TTS, speculative pre-fetch, ETL post-chat idle, e anti-alucinação via RAG aterrado.

## Comandos

```bash
pip install -r requirements.txt
python main.py                          # ou: uvicorn main:app --host 0.0.0.0 --port 8000

pip install -r requirements-dev.txt     # deps de teste (pytest, pytest-asyncio)
pytest                                   # suíte roda sem GPU/rede (usa fakes)
```

Servidor em `http://localhost:8000`. Há uma suíte `pytest` (pasta `tests/`) cobrindo a
lógica pura e sensível — gate de relevância, buffer anti-sentinela, chunker, latência —
com fakes de LLM/TTS/store (sem GPU nem rede). Não há linter ou build configurados.

**Ambiente:** o projeto roda na env conda `llama-omni` (Python 3.10.20) — o `python` no
PATH do Windows costuma ser o atalho falso da Microsoft Store. Rode via caminho absoluto:
`C:\ProgramData\miniconda3\envs\llama-omni\python.exe -m pytest`.

Configuração via `.env` (prefixo `MENTE_`), sem tocar no código — ex.: `MENTE_N_CTX=4096`, `MENTE_RAG_SCORE_CONFIDENT=0.7`. Todos os campos configuráveis estão em [config.py](config.py).

## Arquitetura

Wiring fino em [main.py](main.py) (lifespan cria os serviços e injeta em `AppContext`); toda a lógica vive nos módulos abaixo. Nenhum módulo de domínio conhece o WebSocket diretamente — o pipeline do agente recebe um callback `send(dict) -> bool`.

- **[config.py](config.py)** — `Settings` (Pydantic), incluindo o dicionário fonético inglês→PT-BR usado pelo TTS.
- **[state.py](state.py)** — `AppContext` (DI container em `app.state.ctx`) e `SessionMemory` (histórico de chat, "memória fresca da sessão", fila de ETL — todas `deque` com `maxlen` para não crescer sem fim).
- **[llm.py](llm.py)** — `LlamaManager`. GPU serializada por um `ThreadPoolExecutor(max_workers=1)` ("gpu-infer"): garante estruturalmente que dois decodes nunca rodam juntos na GPU. Cancelamento (barge-in) usa `stop_event` por requisição; o `asyncio.Lock` só é liberado depois que a thread realmente terminou (sem overlap de VRAM).
- **[audio.py](audio.py)** — `SttService` (faster-whisper / CTranslate2; device via `resolve_device`; suba `MENTE_WHISPER_MODEL=large-v3` para máxima qualidade), `TtsService` (Piper), `SentenceChunker` (quebra streaming de tokens em frases prontas para TTS, ignorando abreviações/decimais, com flush por tamanho).
- **[rag.py](rag.py)** — `EmbeddingProvider` (singleton; device via `resolve_device`, `auto` usa GPU se houver), `VectorStore` (Chroma com **distância de cosseno** — não o L2 padrão, pois os embeddings não são normalizados e os thresholds do gate são de escala cosseno; reindex incremental por `mtime`, chunking por cabeçalho Markdown via `split_markdown`, dedup por `source`), `WebSearcher` (DuckDuckGo com **fallback de backend** via `buscar_com_fallback`, cache LRU, speculative pre-fetch). **Deep-fetch + RAG efêmero**: o `ddgs.text()` devolve só snippets (título+1-2 frases) — raso demais para perguntas numéricas/específicas, onde o LLM anti-alucinação respondia "Não tenho informações suficientes" mesmo com a web "respondendo". A correção abre o CORPO das top-N páginas (`httpx` async), extrai o texto principal (`trafilatura`), atomiza e RANKEIA os trechos contra a pergunta com o **mesmo embedding do VectorStore** (`rankear_por_similaridade`, cosseno; nada é indexado — RAG efêmero), passando ao LLM só os melhores dentro de um orçamento de chars. Cai de volta pros snippets se o fetch falhar/estiver off (`MENTE_WEB_FETCH_ENABLED=false`) ou sem embeddings (testes). O `EmbeddingProvider` é criado uma vez em [main.py](main.py) e injetado em `VectorStore` E `WebSearcher`. **Trocar a métrica de distância exige recriar o banco vetorial** (apagar `banco_vetorial_cerebro`).
- **[agent.py](agent.py)** — `QueryOptimizer` (resolve pronomes cruzados via LLM), `Agent.pipeline_resposta` (orquestra cache-hit local/RAM → escalada para web), `LatencyTracker` (TTFT/TTFA), roteamento aditivo de ferramentas (`_rotear`/`_pipeline_tools`), `EtlProcessor` (destila conhecimento novo em ÁTOMOS Zettelkasten no idle — tanto as pesquisas web da fila quanto o **histórico da conversa** (`summarize_dump` agora atomiza em vez de gerar um resumo estruturado), sempre cedendo a GPU para inferência interativa via `ctx.interactive_idle`). **Ciclo de vida do conhecimento** (`#conhecimento_novo`): todo átomo auto-colhido (web + conversa + o contexto amplo do pre-fetch, que é a "curiosidade" enfileirada em `_prefetch`) nasce com a tag `#conhecimento_novo`. Quando um átomo é de fato USADO numa resposta local (estágio Banco não-sentinela), `_consolidar_fontes` remove a tag dos arquivos-fonte (`LocalResult.fontes` reporta quais chunks entraram no contexto) — promoção idempotente e em background. Assim a base cresce da curiosidade do usuário e "amadurece" o que ele realmente reusa. **Um arquivo por átomo** (`_salvar_atomos` + `dividir_atomos`, Zettelkasten puro): a síntese do LLM (vários `##`) é fatiada num `.md` por ideia, então a promoção é precisa por átomo — só o que foi reusado perde a tag, não os vizinhos que calharam no mesmo documento.
- **[tools.py](tools.py)** — function calling ADITIVO. Gate lexical `talvez_acao` (só mensagens de AÇÃO acionam o roteador LLM; pergunta comum não paga a chamada extra → TTFA preservado). Roteador via JSON (`parse_decisao`), não o tool-calling nativo do llama.cpp. `ToolRegistry` + ferramentas (calcular, hora_atual, salvar_nota, listar_notas, ler_nota, buscar_web) e os **agentes de agenda/lista** (criar_lembrete, listar_lembretes, cancelar_lembrete, avisar_quando, agendar_briefing, adicionar_item, ler_lista, remover_item) e a **captura rápida** (capturar_nota → inbox `Inbox_Captura.md` no vault; a revisão/atomização fica pro idle) , o **health-check** (status_sistema → autoteste falável dos serviços .ready), a **trilha de auditoria** (auditoria_hoje → "o que você fez hoje"; ações mutantes têm `auditavel=True` e são gravadas na tabela `auditoria`) e o **modo confidencial** (#5, meta-comando no `_fluxo_mestre`: `mem.confidencial` faz o turno viver só na RAM — sem dump/SQLite/ETL/pre-fetch/lacuna). Loop agêntico CAPADO por `max_tool_steps`; ferramentas `terminal=True` saem no 1º passo. As ferramentas de agenda/lista têm `registra_conhecimento=False`: o turno ("me lembra de X") NÃO alimenta o dump que o idle atomiza — a persistência delas é a tabela/nota, não o Zettelkasten.
- **[mestre.py](mestre.py)** — **palavra-mestre**: um fluxo ISOLADO para acionar os agentes. Quando a mensagem COMEÇA pela palavra-mestre (`MENTE_PALAVRA_MESTRE`, default "mestre"), ela é tratada como COMANDO de agente, não como pergunta — sem a palavra, o pipeline de conhecimento de hoje não muda. `separar` detecta/remove a palavra (só a 1ª conta). `parse_rapido(comando, agora)` resolve os comandos REGULARES por regex, SEM LLM (listas add/ler/remover, listar/cancelar lembrete, alarme só-horário) e devolve `tools.Decisao`; puro/testável, `agora` injetado. O que não casa (lembrete COM mensagem, watcher, composto) devolve None e o `Agent._fluxo_mestre` cai no roteador LLM; se NEM o roteador achar uma ação, o comando é RECUSADO (isolamento rígido) e REGISTRADO em `db.registrar_comando_desconhecido` (tabela `mestre_nao_reconhecido`) como melhoria a revisar. Comando de agente nunca vira conhecimento (não alimenta o dump).
- **[agenda.py](agenda.py)** — parser de tempo PT-BR **puro/testável, sem dependência nova** (o instante de referência é INJETADO, como `normalizar_atomo`). `parse_quando(texto, agora) -> (primeiro_disparo, recorrencia)` cobre relativo ("daqui a 10 min"), absoluto ("amanhã às 8h", "meio-dia") e recorrente ("todo dia às 7h", "toda segunda", "a cada 30 min"). O que não casa devolve `(None, None)` — a ferramenta pede pra reformular em vez de agendar no horário errado. `proximo_disparo` calcula a próxima ocorrência de uma recorrência.
- **[scheduler.py](scheduler.py)** — `SchedulerService`: a "responsabilidade contínua" dos agentes tipo-Alexa (o que o ETL idle NÃO é — ele é oportunista, não cron). Loop de background (retido em `ctx.track_task`, iniciado no lifespan) que lê a tabela **`agendamentos`** (persistente: sobrevive a restart) e dispara os vencidos, fazendo PUSH FALADO para as sessões vivas (`ctx.sessoes` → `safe_send` com `{"tipo":"proativo"}` + `{"tipo":"audio"}`; o front abre uma bolha própria com 🔔). Três tipos: `lembrete` (alarme/timer, único ou recorrente), `watcher` ("me avise quando X" — recorrente, a cada checagem busca na web e pergunta ao LLM se a condição ocorreu, `SYS_WATCHER`), `briefing` (flash briefing diário, `SYS_BRIEFING`). **Sem ouvinte não perde**: o disparo vira `pendente_entrega` e é reentregue na próxima conexão (o WS chama `entregar_pendentes` no accept). **Respeita a GPU serializada**: watcher/briefing só chamam o LLM após `interactive_idle.wait()` e com `preemptible=True` — a conversa ao vivo passa na frente, igual ao ETL.
- **[verbosidade.py](verbosidade.py)** — governador de verbosidade (#7, "Uma Frase Basta"): `classificar(pergunta)` puro decide o tamanho/latência da resposta (factual curta → 1 frase com teto de tokens menor; "explica/por quê/detalhe" → resposta cheia). O `Agent._responder_contexto`/`_responder_web` recebem `max_tokens`/`instrucao_extra` do nível.
- **Síntese sob Demanda (#23)** — "o que eu sei sobre X" tem FLUXO PRÓPRIO em `Agent._sintese_sob_demanda` (detectado por `extrair_tema_sintese`, puro): `VectorStore.buscar_conteudos` recupera muitos átomos crus, o pipeline os resume em LOTES que cabem no n_ctx (map, `prompt_sintese_tema_map`) e combina os parciais numa fala (reduce, streaming) — map-reduce que evita estourar o contexto num tema grande.
- **[textutils.py](textutils.py)** — normalização de texto e extração de keywords (sem acento/stopwords) usada para aterramento léxico e limpeza de query.
- **[ws.py](ws.py)** — `LiveSession`: máquina de estados do WebSocket `/ws/chat_live` (VAD por RMS no servidor, barge-in cancela o pipeline em andamento). `_finalizar_sessao` dispara o ETL idle UMA vez, tanto no `end_session` explícito quanto no **disconnect** (rede de segurança: antes, cair a conexão sem `end_session` perdia a atomização da conversa). **Conversas**: o cliente controla a conversa ativa via `set_conversa` (reassocia o id na reconexão), `nova_conversa` (id novo + contexto limpo) e `carregar_conversa` (recarrega os turnos do SQLite na RAM p/ continuar). Todo turno é gravado com `memory.conversa_id`, e o histórico agrupa por ele.
- **[telemetry.py](telemetry.py)** — logs coloridos thread-safe (`telemetry.track/warn/error`) e `Database` (SQLite: histórico de chat com `conversa_id`, log de ETL, métricas, e **latência TTFT/TTFA por resposta** via `save_latency`; médias expostas em `/api/metrics`). **Histórico por CONVERSA** (não turnos soltos): `get_conversations` agrupa por `conversa_id` (turnos legados sem id caem por dia via `COALESCE`) e `get_conversation` devolve todos os turnos de uma para reabrir; endpoints `/api/conversas` e `/api/conversa/{id}`. Migração idempotente adiciona `conversa_id` a bancos antigos. Nunca usar `except: pass` — todo erro passa por `telemetry.error`.
- **[prompts.py](prompts.py)** — todos os prompts de sistema/tarefa centralizados aqui (extrator de query, filler, resposta principal, síntese ETL de web e de conversa). A tag de maturidade é `prompts.TAG_NOVO` (`#conhecimento_novo`); `TAG_ATOMO` é `#zettelkasten_atomico`.

### Pipeline de resposta (`Agent.pipeline_resposta`)

1. `QueryOptimizer` extrai termos de busca da pergunta (resolvendo pronomes via histórico recente).
2. Busca local no `VectorStore` + memória de sessão filtrada por tema (`_ram_relevante`).
3. **Gate de relevância** (correção do "Cache Hit falso" — ver seção abaixo): só é Cache Hit se houver aterramento léxico (chunk menciona keyword da pergunta) OU confiança semântica alta (`distância < rag_score_confident`).
4. Se Cache Hit: responde com streaming, mas segura o áudio/tokens até confirmar que a resposta não é o sentinela anti-alucinação `"não tenho informações suficientes"` — se confirmar, escala para web sem nunca "falar" o sentinela (preserva TTFA).
5. Cache Miss (ou escalada): dispara um filler falado para mascarar latência, busca na web, responde em streaming, e enfileira o resultado para o ETL idle.

### Correção do "Cache Hit falso"

Ver [README.md](README.md) para o diagnóstico completo. Resumo: o gate antigo tratava "tem algum contexto" como Cache Hit; com um vault grande, quase toda pergunta achava algo vagamente parecido e a web nunca era consultada. A correção exige contexto **relevante** (aterramento léxico via `textutils.contem_alguma` OU `rag_score_confident`). O botão de calibração é `MENTE_RAG_SCORE_CONFIDENT` (default `0.8`; menor = mais rígido/mais web, maior = mais confiança no local) — cada pergunta loga `[LOCAL] melhor_dist=... relevante=...` para calibrar.

### Convenções

- Toda chamada bloqueante/CPU-bound (IO de arquivo, Whisper, Piper, embeddings, SQLite) passa por `asyncio.to_thread`.
- Erros nunca são engolidos silenciosamente — sempre `telemetry.error(modulo, mensagem, exc)`.
- Comentários no código explicam o *porquê* (ex.: por que um lock existe, que bug histórico uma heurística corrige) — mantenha esse padrão ao editar esses módulos.
- STT parcial (transcrição em tempo real/streaming) é uma não-feature intencional — não implementar sem pedido explícito (ver README).
